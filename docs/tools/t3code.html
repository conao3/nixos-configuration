T3 Code

マシン上のコーディングエージェント (Codex / Claude / Cursor / Grok Build / OpenCode / Antigravity) を、 デスクトップ・Web・スマホから操作する「エージェントハーネスのコントロールサーフェス」。 サブスクリプションの契約済みエージェントをそのまま使い、T3 Code 自体は課金しない (pingdotgg/t3code、v0.1 系でまだ初期段階)。

この環境での導入

llm-agents flake input の t3code (CLI) と t3code-desktop (Electron アプリ) を home-manager/features/t3code.nix で入れ、home-profile/full-gui.nix 経由で GUI ホスト (eos / helios) に配る。nixpkgs の t3 は別物 (tee) なので注意。

コマンド用途
t3code-desktopデスクトップアプリ。メニューの「T3 Code」(t3code.desktop) からも起動できる
t3CLI / サーバ。t3code というコマンド名は無い
公式のインストーラ (curl … | sh) や t3 update / t3 uninstall は ~/.local/bin を書き換える前提なので、nix 管理のこの環境では使わない。更新は make update で llm-agents を上げて make switch する。

データは ~/.t3/ に作られる (userdata/ に DB・設定・keybindings.json、worktrees/ に git worktree)。

初期設定

1. プロバイダの認証

T3 Code 自体は認証を持たず、マシンに入っているエージェント CLI のログインを使う。少なくとも 1 つ認証済みなら使い始められる。

プロバイダ認証この環境の状態
Claudeclaude auth loginログイン済み (conao3 / agent001 をインスタンスとして登録)
Codexcodex login もしくは Settings → Providers の「Connect with ChatGPT」agent001 / agent002 をインスタンスとして登録 (既定の ~/.codex は未ログイン)
Cursoragent login未確認
OpenCodeopencode auth login未確認

アプリの Settings → Providers で使うプロバイダを有効にする。プロジェクトを選んでいるときのスイッチは、そのプロジェクトだけの有効・無効になる (Reset で全体設定に戻る)。

1b. マルチアカウント (プロバイダインスタンス)

同じプロバイダを設定ディレクトリ違いで複数登録できる。Settings → Providers の「Add instance」か、 ~/.t3/userdata/settings.json の providerInstances で宣言する。 スレッドのモデルピッカーでアカウントを選べ、同じ設定ディレクトリのインスタンス間なら既存スレッドの途中で切り替えられる。

ドライバ設定ディレクトリの項目対応する環境変数
claudeAgenthomePathCLAUDE_CONFIG_DIR
codexhomePath (任意で shadowHomePath)CODEX_HOME

この環境で登録済みのインスタンス (各エージェント用の設定ディレクトリを指す。codex.agent001 等のラッパーと同じ CODEX_HOME):

{
  "providerInstances": {
    "claude_conao3":   { "driver": "claudeAgent", "displayName": "Claude conao3",   "config": { "homePath": "/home/conao/.agents/.claude.conao3" } },
    "claude_agent001": { "driver": "claudeAgent", "displayName": "Claude agent001", "config": { "homePath": "/home/conao/.agents/.claude.agent001" } },
    "codex_agent001":  { "driver": "codex", "displayName": "Codex agent001", "config": { "homePath": "/home/conao/.agents/.codex.agent001" } },
    "codex_agent002":  { "driver": "codex", "displayName": "Codex agent002", "config": { "homePath": "/home/conao/.agents/.codex.agent002" } }
  }
}
homePath を空にした既定インスタンス (claude / codex) は、アプリを起動したシェルの CLAUDE_CONFIG_DIR と ~/.codex を使う。メニューから起動すると環境変数が違うので、 アカウントを固定したいときは上のようにパスを明示したインスタンスを使う。設定ファイルはアプリが書き換えるので、 編集するときはアプリを終了してから行う。

Codex だけで共有したい場合 (履歴や設定を共有しつつ auth.json だけ分ける) は shadowHomePath を使う。詳細は上流の docs/user/providers-codex.md。

2. プロジェクトの追加

アプリのサイドバーから追加するか、CLI で追加する。

t3 project add ~/ghq/github.com/conao3/nixos-configuration
t3 project rename <id> <title>
t3 project remove <id>

追加済み: nixos-configuration。ターミナルから「今いるディレクトリ」で開くなら、アプリ起動中に t3 app (パス指定可)。

3. 推奨しておく設定

  • Settings → General → New threads → Permissions: 初期値は Full access。慎重に始めるなら Supervised か Auto に変える (プロジェクトごとの上書きも可)。
  • Settings → Source Control → Worktree branch naming: 自動命名される worktree ブランチの接頭辞 (既定 t3/)。
  • Settings → Keybindings: 後述。~/.t3/userdata/keybindings.json を直接編集してもよい。

基本の使い方

  1. プロジェクトを選び、新しい thread を作る (thread = 1 つのエージェントとの会話・作業単位)。
  2. コンポーザでプロバイダ / モデル / effort / 権限モードを選んでメッセージを送る。
  3. エージェントが承認を求めたら、会話内で承認・拒否する。質問が来たら質問パネルで答える。
  4. 右パネルで diff と PR を確認する。thread は worktree で並列に走らせられる (mod+shift+l で直前の worktree を再利用)。
  5. ターミナルを thread に開ける。止めたいときは thread.stop (既定のショートカットなし、Settings で割り当て)。

設定 → Scheduled tasks では定期実行タスクと、外部サービス (GitHub の PR・CI 失敗など) から URL を叩いて起動する webhook タスクも作れる。

権限モード

モード挙動
Supervisedコマンドとファイル変更のたびに承認を求める
Auto-accept editsファイル編集は自動承認、その他は承認が要りうる
Autoプロバイダの自動レビューで定型の操作を承認し、他は確認する
Full access承認なしでコマンドと編集を実行する

モードは thread 単位で、コンポーザで選ぶ。Claude は自身の設定で bypass が無効なら Full access でも確認を出すことがある。

設定ファイルの書き方

~/.t3/userdata/keybindings.json は規則の JSON 配列。T3 Code が既定の規則でファイルを作り、更新で増えた既定は次回起動時に追記される (自分で変えたコマンドの割り当ては上書きされない)。不正な規則は無視され、ファイルが読めなければ既定に戻る。 最後に書いた、キーと条件の両方が合う規則が勝つ (別のコマンドのものでも同じ)。 同じキーの既定を上書きするときは、後ろに規則を足す。 

[
  { "key": "mod+g", "command": "terminal.toggle" },
  { "key": "mod+shift+g", "command": "terminal.new", "when": "terminalFocus" }
]

キーは + でつなぐ (mod+shift+d など)。修飾キーは mod / cmd (meta) / ctrl (control) / alt (option) / shift。when で使える文脈: terminalFocus terminalOpen previewFocus previewOpen modelPickerOpen usagePageOpen composerFocus composerDraft turnRunning editableFocus isWeb isDesktop (未知の名前は false)。! && || と括弧で組み合わせる。

mod+1〜9 の thread 移動は、ブラウザのタブ切り替えを奪わないよう isDesktop が付いている。 ブラウザ版で使うなら Settings で条件を外す。ブラウザでは mod+w がブラウザのタブを閉じ、mod+shift+t もブラウザが先に取ることがあるので、 rightPanel.close と terminal.close を alt+w などに付け替える。 Linux のデスクトップ環境側のショートカットと被る場合も、Settings で別のキーを選ぶ。

出典: 上流の docs/user/keybindings.md と packages/shared/src/keybindings.ts の DEFAULT_KEYBINDINGS。

リモートアクセス

エージェントはサーバのあるマシンで動き、スマホ (iOS / Android) や別のブラウザ・デスクトップから操作できる。ホストは起動し続けている必要がある。

  • T3 Connect: ポート開放なし。デスクトップは Settings → Connections で有効化、CLI は t3 connect。
  • LAN / tailnet のペアリング: t3 serve --host <private-ip>、起動済みなら t3 pair で QR を出してスマホで読む。127.0.0.1 は同一端末からしか届かない。
  • Tailscale HTTPS: --tailscale-serve でサーバを tailnet に HTTPS で出せる。

この環境の設定 (Tailscale HTTPS)

  • nixos/configuration.nix で tailscale の --operator=conao を指定済み (sudo なしで tailscale serve を設定できる)。
  • eos の *:443 は portless proxy (nixos/portless.nix) が使っていて、tailscale の 443 を横取りして TRAEFIK DEFAULT CERT の証明書エラーになる。そのため 8443 で公開する: tailscale serve --https=8443 --bg http://127.0.0.1:3773 (設定済み・再起動後も残る)。
  • URL: https://conao-nixos-eos.tail6dd115.ts.net:8443/ (tailnet 内だけ。Funnel は使っていない)。
  • 端末のペアリング: eos で t3 pair --tailscale --tailscale-serve-port 8443 --label phone を実行し、出た QR / URL を端末で開く (トークンは 5 分で失効、端末ごとに発行する)。
  • 止める: tailscale serve --https=8443 off。接続済みの端末の取り消しは t3 auth session list / t3 auth session revoke <id>。
  • サーバはデスクトップアプリが持っているので、eos でアプリが起動していないとつながらない。
tailnet や T3 Connect で出すと、そのマシンのエージェントを動かせる経路が増える。ペアリングは端末ごとに新しい一回限りのリンクを使い、権限モードも合わせて見直す。

MCP 連携

T3 Code が起動していない手元の Claude Code / Codex / ChatGPT からも、環境の MCP サーバ (…/mcp) 経由で thread の読み取りや起動ができる。サインインは初回に承認し、権限は Read only (既定) から Full access まで選ぶ。Settings → Connections の「Copy MCP URL」で URL を取る。

claude mcp add --transport http t3 https://<environment-address>/mcp
claude mcp login t3

codex mcp add t3 --url https://<environment-address>/mcp
codex mcp login t3

エージェントが認証情報を送るのは https か localhost のみ。平文 http の LAN アドレスでは存在の検出まででサインインを終えられない。
